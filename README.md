# ai-ch

**ai-ch** — приватное веб-приложение для работы с ИИ: личные чаты, потоковые ответы, загрузка файлов, память, веб-поиск и настраиваемая маршрутизация запросов между моделями.

Приложение построено на FastAPI и использует OpenAI-совместимые API. Пользователь работает через единый интерфейс без выбора модели на главном экране; последовательности моделей настраиваются администратором.

## Возможности

### Чаты и ответы
- Личные чаты и история сообщений.
- Потоковая генерация ответа.
- Продолжение диалога и обработка состояний сообщения.
- Оценка ответов.
- Отображение Markdown, кода и математических формул.
- Работа с прикреплёнными файлами и извлечённым из них текстом.

### Модели и маршрутизация
- Отдельные наборы моделей (**Model Sets**) для разных типов задач.
- Упорядоченная цепочка моделей: при ошибке одного провайдера роутер пробует следующую модель.
- Ограничение числа одновременных запросов к каждой модели.
- Очередь задач и возможность отменить генерацию.
- Учёт входных, выходных и кэшированных токенов, а также расходов по вызовам API.
- Настройки провайдеров и параметров генерации управляются через админ-панель. В обычном режиме все AI-задачи используют первую активную модель основного набора MAIN без автоматической маршрутизации и переключения на резервные модели.

### Файлы, память и поиск
- Загрузка файлов и их привязка к сообщениям.
- Извлечение текста из поддерживаемых документов для передачи модели.
- Пользовательская память.
- Веб-поиск через настроенный сервис SearXNG с передачей найденного контекста модели.

### Аккаунты и администрирование
- Авторизация и пользовательские сессии.
- Административная панель для управления пользователями, моделями, наборами моделей и лимитами.
- Тарифы Free и Pro с настраиваемыми ограничениями.
- Учёт использования моделей и расходов.
- Начальная настройка учётной записи администратора через переменные окружения.

## Технологии

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2 (async), aiosqlite, Pydantic Settings.
- **Frontend:** HTML, CSS и vanilla JavaScript; отдельная сборка frontend не требуется.
- **База данных:** SQLite.
- **AI API:** OpenAI-совместимый API, потоковая передача ответа.
- **Поиск:** SearXNG (если настроен и включён).
- **Исполнение кода:** отдельная изолированная песочница, если соответствующая функция включена.

## Запуск

Требуется Python 3.12 и зависимости из `requirements.txt`.

```bash
pip install -r requirements.txt
uvicorn app.main:fastapi --host 0.0.0.0 --port 8000
```

Если точка входа в используемой версии приложения экспортирует объект с другим именем, команду запуска необходимо согласовать с `app/main.py`.

## Конфигурация

Настройки читаются из переменных окружения и файла `.env`. В зависимости от используемых функций могут потребоваться:

- параметры быстрой модели: `FAST_QWEN_BASE_URL`, `FAST_QWEN_API_KEY`, `FAST_QWEN_MODEL_ID`;
- секрет сессий: `SESSION_SECRET`;
- адрес SearXNG: `SEARXNG_URL`;
- адрес песочницы: `SANDBOX_URL`;
- параметры администратора: `ADMIN_EMAIL`, `ADMIN_PASSWORD`;
- параметры лимитов, таймаутов и параллельности.

Не добавляйте `.env`, API-ключи, пароли или токены в Git. Используйте значения из актуальной конфигурации приложения и задавайте секреты через защищённые переменные окружения.

### Автоматический выбор ответа между основной моделью и быстрым Qwen

AI CH параллельно отправляет запрос основной модели MAIN и отдельной быстрой модели Qwen. Побеждает первая модель, завершившая полноценный ответ. Если основной ответ завершён раньше, ответ Qwen отбрасывается. Если первой ответила Qwen, её результат принимается только при условии, что он полный и не содержит служебного маркера отказа. Быстрая модель должна отвечать только на лёгкие и средние запросы и возвращать `[[AICH_FAST_QWEN_DECLINE]]`, когда не уверена или ответ может превысить 8 000 выходных токенов. В таком случае AI CH ждёт ответ основной модели. Сам API-запрос Qwen также ограничен 8 000 выходными токенами; ответ, оборванный по лимиту, не используется.

В Render → Environment (или в локальном `.env`) настройте три обязательные переменные быстрой модели:

- `FAST_QWEN_BASE_URL` — базовый URL OpenAI-совместимого API, обычно оканчивается на `/v1`;
- `FAST_QWEN_API_KEY` — API-ключ этого Qwen endpoint;
- `FAST_QWEN_MODEL_ID` — точный внешний ID модели, который принимает этот endpoint.

Необязательные `FAST_QWEN_TIMEOUT` и `FAST_QWEN_PRICE_IN` / `FAST_QWEN_PRICE_OUT` / `FAST_QWEN_PRICE_CACHE` управляют таймаутом и учётом расходов. По умолчанию цена быстрой модели равна нулю; если провайдер списывает деньги, укажите реальные тарифы. Когда любой из трёх параметров подключения отсутствует, приложение использует только основную модель.

Старая кнопка Think и переменные `THINK_*` больше не используются. Если в Render были заданы старые `QWEN_*` переменные, переопределяющие основную модель MAIN, удалите эти переменные, чтобы основной провайдер определялся активной записью Model Sets.

### Основная модель

Основная модель отвечает за все запросы, если её ответ завершился первым, и остаётся настроенной в **AI CH → Admin → Model Sets**: выберите активный MAIN-набор и его первую активную модель. Для этой схемы не задавайте в Render старые `QWEN_*` переменные переопределения: они предназначены для обратной совместимости и могут подменить провайдера, сохранённого в Model Sets. Параметры быстрой дополнительной модели задаются только через `FAST_QWEN_*`, описанные выше.

Код-агент ограничен максимум тремя обращениями к модели на один цикл выполнения кода (параметр `CODE_AGENT_MAX_STEPS`, верхняя граница — 3). Для обычной задачи цель — 2–3 обращения: собрать код, стили, данные и текст результата одним блоком `run`, затем проверить и при необходимости исправить результат. Название чата Код-агент формирует локально из первого запроса, поэтому отдельный вызов модели только ради названия не добавляется. При веб-поиске Код-агент также извлекает поисковый запрос локально, не расходуя ещё один вызов модели только на формулировку запроса; умный поисковый запрос в обычном чате не изменён. Количество внутренних выполнений не показывается отдельными нумерованными шагами: в чате отображается единая сворачиваемая панель результата, а ссылки на созданные файлы сохраняются.

`QWEN_PROVIDER` — метка типа провайдера; сам транспорт в этой версии использует OpenAI-совместимый формат `/v1/chat/completions` с Bearer-авторизацией. Поэтому смена метки не превращает несовместимый API в OpenAI-совместимый. После изменения окружения перезапусти/redeploy основной сервис.

### Озвучка ответов

Под кнопкой «Прослушать ответ» backend создаёт аудио через OpenAI-compatible API с методом `POST /audio/speech`. Ключ не передаётся в браузер и не должен попадать в Git.

В Render в разделе **Environment** основного веб-сервиса задайте:
- `TTS_BASE_URL` — базовый адрес API (например, адрес, оканчивающийся на `/v1`; приложение добавляет `/audio/speech`);
- `TTS_API_KEY` — секретный ключ провайдера;
- `TTS_MODEL` и `TTS_VOICE` — поддерживаемые провайдером модель и голос;
- `TTS_RESPONSE_FORMAT=mp3` — формат аудио (также предусмотрены `opus`, `aac`, `flac`, `wav`, `pcm`);
- при необходимости `TTS_TIMEOUT=180`, `TTS_MAX_CHARS=30000`, `TTS_CONCURRENCY=2`.

Точный URL, модель, голос и допустимые форматы зависят от выбранного TTS-провайдера. Нужен API, совместимый с OpenAI `/audio/speech`; одного произвольного base URL недостаточно. После изменения переменных выполните redeploy/restart сервиса.

Аудиоверсии хранятся в `DATA_DIR/audio` рядом с базой приложения и отдаются только владельцу сообщения через авторизованные endpoints. На Render для сохранения аудио между перезапусками нужен persistent disk, смонтированный в тот же `DATA_DIR`; без постоянного диска файлы на временной файловой системе могут исчезнуть после перезапуска.

## Песочница

Код модели выполняется в отдельном runner-сервисе, а не в процессе FastAPI. Runner ограничивает время выполнения и размер вывода, запускает код с минимальным окружением и может передавать небольшие созданные файлы обратно в приложение через API. В Render сервисы не имеют общей папки; поэтому для передачи файлов используется ограниченный base64-пакет (до 4 MiB на файл и 8 MiB суммарно за запуск). Слишком большие артефакты через этот путь не передаются.

### Render: подключение отдельной песочницы

1. В Render создай **отдельный Web Service** из этого же репозитория. Выбери Docker runtime, контекст Docker — корень репозитория, Dockerfile path — `sandbox/Dockerfile`. Runner должен находиться в том же регионе, что и `ai-ch`.
2. В переменных окружения runner-сервиса задай `SANDBOX_API_KEY` — длинный случайный секрет. Не коммить его в Git. В образе уже включена обязательная проверка ключа (`SANDBOX_REQUIRE_AUTH=1`), каждый запуск выполняется под отдельным непривилегированным UID (постоянный проект использует свой UID), без передачи переменных окружения сервиса дочернему Python-процессу.
3. В основном сервисе `ai-ch` задай `SANDBOX_URL` равным реальному публичному адресу runner-сервиса, например `https://имя-сервиса.onrender.com`, и установи **тот же самый** `SANDBOX_API_KEY`. Не копируй пример адреса буквально: используй URL, который Render выдал созданному сервису.
4. После сохранения переменных перезапусти оба сервиса. Первый запуск может задержаться, если бесплатный runner был выключен из-за простоя. Проверяй логи и основного приложения, и runner, если песочница не отвечает.

Публичный адрес runner защищён bearer-ключом: `/run` и `/project/{id}` отклоняют запросы без него. Эту настройку нельзя убирать при размещении runner на публичном URL. Созданные файлы переносятся в основное приложение только в пределах указанных выше ограничений.

**Ограничения бесплатного Render:** файловая система сервиса по умолчанию временная, поэтому файлы проекта внутри runner не гарантированно сохраняются после пересоздания сервиса. Для постоянных проектов нужен отдельный постоянный том (платный план) или внешний объектный storage. Runner является отдельной границей процесса/сервиса, но это не эквивалент полностью изолированной VM: не используй его для запуска заведомо враждебного кода с секретными данными.

Если `SANDBOX_URL` не настроен, приложение не переключается незаметно на исполнение кода внутри публичного веб-сервиса: оно возвращает понятную ошибку. Локальный fallback можно включить только явной переменной `SANDBOX_ALLOW_LOCAL=1`; для публичного multi-user приложения этого делать не следует.

## Веб-поиск на Render и локально

Веб-поиск включён в стандартный запрос чата. Если `SEARXNG_URL` задан, сначала используется SearXNG; если адрес пуст, сервис недоступен или выдаёт пустые результаты, приложение пробует DuckDuckGo, а затем Bing. Все выдаваемые источники фильтруются до URL со схемой HTTP или HTTPS. Эти публичные поисковики могут ограничивать запросы или быть недоступны из отдельных сетей; успешность каждого внешнего запроса не гарантируется. Для локального SearXNG задай `SEARXNG_URL` адресом, доступным именно из контейнера/сервиса приложения.
