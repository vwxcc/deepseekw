# ai-ch

**ai-ch** — приватное веб-приложение для работы с ИИ: личные чаты, потоковые ответы, загрузка файлов, память, веб-поиск и настраиваемая маршрутизация запросов между моделями.

Приложение построено на FastAPI и использует OpenAI-совместимые API. Пользователь работает через единый интерфейс без выбора модели на главном экране; последовательности моделей настраиваются администратором.

## Возможности

### Чаты и ответы
- Личные чаты и история сообщений.
- Потоковая генерация ответа.
- Продолжение диалога и обработка состояний сообщения.
- Оценка ответов.
- Отображение Markdown, кода и математических формул.
- Работа с прикреплёнными файлами и извлечённым из них текстом.

### Модели и маршрутизация
- Отдельные наборы моделей (**Model Sets**) для разных типов задач.
- Упорядоченная цепочка моделей: при ошибке одного провайдера роутер пробует следующую модель.
- Ограничение числа одновременных запросов к каждой модели.
- Очередь задач и возможность отменить генерацию.
- Учёт входных, выходных и кэшированных токенов, а также расходов по вызовам API.
- Настройки провайдеров, моделей, параметров генерации и порядка fallback управляются через админ-панель.

### Файлы, память и поиск
- Загрузка файлов и их привязка к сообщениям.
- Извлечение текста из поддерживаемых документов для передачи модели.
- Пользовательская память.
- Веб-поиск через настроенный сервис SearXNG с передачей найденного контекста модели.

### Аккаунты и администрирование
- Авторизация и пользовательские сессии.
- Административная панель для управления пользователями, моделями, наборами моделей и лимитами.
- Тарифы Free и Pro с настраиваемыми ограничениями.
- Учёт использования моделей и расходов.
- Начальная настройка учётной записи администратора через переменные окружения.

## Технологии

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2 (async), aiosqlite, Pydantic Settings.
- **Frontend:** HTML, CSS и vanilla JavaScript; отдельная сборка frontend не требуется.
- **База данных:** SQLite.
- **AI API:** OpenAI-совместимый API, потоковая передача ответа.
- **Поиск:** SearXNG (если настроен и включён).
- **Исполнение кода:** отдельная изолированная песочница, если соответствующая функция включена.

## Структура проекта

```text
app/
  ai/
    router.py       очередь задач, маршрутизация, fallback и стриминг
    model_sets.py   наборы моделей и их порядок
    providers.py    обращения к AI-провайдерам
    prompts.py      системные инструкции и обработка промптов
  routers/          HTTP API: чаты, сообщения, файлы, память,
                    модели, лимиты, авторизация и администрирование
  services/         работа с файлами, лимитами, расходами,
                    поиском и песочницей
  config.py         конфигурация приложения
  database.py       подключение к базе данных
  models.py         SQLAlchemy-модели
  main.py           создание FastAPI-приложения
frontend/
  index.html
  css/
  js/
sandbox/            сервер изолированного исполнителя кода
requirements.txt
```

## Запуск

Требуется Python 3.12 и зависимости из `requirements.txt`.

```bash
pip install -r requirements.txt
uvicorn app.main:fastapi --host 0.0.0.0 --port 8000
```

Если точка входа в используемой версии приложения экспортирует объект с другим именем, команду запуска необходимо согласовать с `app/main.py`.

## Конфигурация

Настройки читаются из переменных окружения и файла `.env`. В зависимости от используемых функций могут потребоваться:

- параметры AI-провайдера: `QWEN_API_KEY`, `QWEN_BASE_URL`, `QWEN_MODEL`;
- секрет сессий: `SESSION_SECRET`;
- адрес SearXNG: `SEARXNG_URL`;
- адрес песочницы: `SANDBOX_URL`;
- параметры администратора: `ADMIN_EMAIL`, `ADMIN_PASSWORD`;
- параметры лимитов, таймаутов и параллельности.

Не добавляйте `.env`, API-ключи, пароли или токены в Git. Используйте значения из актуальной конфигурации приложения и задавайте секреты через защищённые переменные окружения.

## Данные приложения

По умолчанию конфигурация задаёт каталог базы данных `/app/data` и каталог файлов `/app/uploads`. Фактические пути можно изменить переменными окружения.

**Важно:** в текущем развёртывании сохранение данных после перезапуска пока работает некорректно. Эта проблема известна и намеренно не исправляется в рамках текущего изменения README. Не считайте сохранность данных после рестарта гарантированной; перед обновлениями и экспериментами учитывайте риск потери данных.

## Песочница

Исполнение кода, если оно включено, должно происходить в отдельной изолированной песочнице, а не в основном процессе веб-приложения. Песочницу следует запускать с минимально необходимыми правами, ограничениями ресурсов и без доступа к интернету, если он не требуется.

Проверки проекта выполняются в собственной тестовой песочнице. Это само по себе не подтверждает корректность всех сценариев в production-развёртывании.

## Разработка

- Изменения интерфейса вносите согласованно с соответствующими API и backend-логикой.
- После изменений проверяйте затронутые сценарии в тестовой песочнице.
- Не считайте состояние локальной копии, GitHub и работающего сервера одинаковым без отдельной проверки.
